01项目定位

YJK 的 .ydb 文件本质是未加密的 SQLite 数据库。本工程把它解析、净化、重组为一份统一中间数据库， 上部结构与基础写入同一份库，由下游 C# Revit 插件（CombineBeam、CreateNewExtern 等）读取并生成模型。

三条强制边界（全链路适用）

  • 只读 YDB，绝不读 DWG —— DWG 仅用于人工验证，不得向中间库反向补齐任何字段。
  • 配筋不从 YDB 提取 —— 由本机网页（foundation_web.py）按型号人工补录。
  • 单位统一 mm / 度 —— 英尺换算与符号对齐由 Revit C# 端负责，Python 原样透传。
列顺序即契约：tbl1–tbl7 的现有列是与 C# 端的固定兼容接口（C# 按下标读取）， 后续只允许在表尾追加双方确认的新列，不得插入、删除或调整顺序。

4.2 基础提取 foundation_handoff.py · 871 行

  • 模式识别：is_foundation_ydb()（:107）探测 7 张必备表（DEF_dais / app_dais / dais_pt / dais_stepH / DEF_Pile / app_Pile / node）。
  • 型号归并：桩型号 = 直径+长度 → PILE-<16位SHA256>；承台型号 = 多边形+厚度+完整局部桩位 → CAP-<16位SHA256>。几何规范化（_canonical_cap_model :190）忽略起始顶点 / 绕向 / 平移 / 旋转，镜像不归并。
  • 配筋保护：重建前快照 tbl5/tbl6 配筋字段，按未变化的 TypeKey 恢复（_snapshot_rebar :311 / _restored_rebar :342）——重新提取不丢人工录入。
  • 显式拒绝（抛 FoundationDataError，不静默猜测）：多阶/圆形承台、斜桩、矩形桩、独立桩、相对标高、声明桩数与模板不符。
  • 单位换算：dBotElevat×1000（m→mm）、ang 弧度→度；app_dais.nj 零基 → node.ID 一基需 +1。

4.3 原子安全更新 handoff_atomic.py · 367 行

所有对正式库的写入都经 atomic_update_database()（handoff_atomic.py:271），五道关卡：

  1. 正式库同目录创建唯一 .pending-* 暂存库，SQLite backup API 一致性快照；
  2. 三重哈希防并发：快照前后 + 暂存基线的全库 SHA-256 必须一致，否则 ConcurrentUpdateError；
  3. writer 只写暂存库 → PRAGMA integrity_check；
  4. 范围指纹：对「非目标表 + 受保护元数据」逐行哈希比对，任何越界改动抛 ScopeViolationError；upper 模式额外对 tbl5–tbl7 + Foundation.* 计算 foundation_contract_sha256；
  5. 复核正式库未变、无活动 WAL sidecar → os.replace 原子替换；失败只清理暂存文件，正式库分毫不动。

4.4 配筋补录网页 foundation_web.py · 287 行

serve_foundation_editor()（:248）：单文件 HTTP 服务，HTML/CSS/JS 全部内嵌，无 CDN、无外网请求、无文件上传。仅绑定 127.0.0.1:8765，启动时生成一次性 URL 令牌（secrets.compare_digest 校验），响应带 CSP / nosniff 安全头。页面为「承台类型 / 桩类型」卡片表单。

06使用方式

命令行

# 上部结构提取（Revit/批处理必须显式传模式）
ydb转换.exe <上部结构.ydb> -o <ydb转换数据库.db> --mode upper
# 基础提取
ydb转换.exe <jccad.ydb>     -o <ydb转换数据库.db> --mode foundation
# 基础提取 + 打开本机补录网页（--web 仅限基础模式）
py .\ydb转换.py ".\基础部分模型\jccad.ydb" -o ".\ydb转换数据库.db" --web
# 只打开已有中间库的补录网页
py .\foundation_web.py ".\ydb转换数据库.db"
  • 省略 source 双击 EXE → 弹出 Win32 原生文件选择框；取消返回 status=cancelled。
  • 省略 -o → 默认网络盘 Y:\数字化课题\数据库\ydb转换数据库.db，回退本地 Revit Addins 目录。
  • 标准输出为单行 JSON：成功含 mode / status / protected_sha256（upper 另含 foundation_sha256）与统计；失败含 error_type / error。
  • 退出码：0 成功 · 1 错误 · 2 用户取消。不得以「进程退出但无成功 JSON」作为可覆盖正式库的依据。

开发与打包

py -m unittest discover -s tests      # 31 例回归（stdout 末行 OK）
py tools\export_pec_wall_check_dxf.py <dtlmodel.ydb> -o .\validation_output\核对.dxf
pyinstaller ydb转换.spec              # 重新打包 dist\ydb转换.exe（改 ydb转换.py 后必须重打包）
本机注意：python 不在 PATH，须用 py（Python 3.13）；工程纯标准库实现，无需 pip install 任何包。
