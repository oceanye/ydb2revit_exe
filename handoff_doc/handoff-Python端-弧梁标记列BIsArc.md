# Handoff：弧梁标记列 BIsArc（供 Revit 端染色人工改弧）

提出日期：2026-09-04
提出方：Revit 插件端（CreateNewExtern 维护）
现象：颛桥模型中 YJK 存在**弧梁**，中间库 tbl1 只有起终点弦线坐标、无任何弧信息，
Revit 端只能生成直梁。维护方决策：**不强求自动生成弧梁**，由人工手改——
插件端先把弧梁**染成醒目颜色**便于定位，为此需要数据侧提供弧标记。
结论先行：**需要 ydb转换.py 在 tbl1 末尾追加 BIsArc 列**；插件端零改动等列上线后即可染色。

## 1. 已核实事实（插件端实测）

* 中间库 tbl1 现有列：`BStartX..BEndZ,BSection,Tag,ID,RvtID,BSConn,BEConn,Ecc,Ecc2,BRotation,BZOffset,BZOffset2`
  ——**无任何弧信息**；
* ydb `tblGrid.idCen` 全库均为 `4294967295`（0xFFFFFFFF 空哨兵），不能作为弧判据；
* 弧梁在 ydb 中的确切表示（弧轴/弧网格的字段或子表）**插件端未定位**，
  由 Python 侧按《YJK 解析说明》确定。

## 2. 输出契约（⚠️ 必须遵守）

1. `tbl1` 末尾追加 **`BIsArc INTEGER`**（0=直梁，1=弧梁；默认 0），列只增不改不插；
2. 判定标准由 Python 侧确定（梁所在网格为弧网格/弧轴即 1），并在转换 result 中
   报告弧梁总数；
3. **弧梁起终点仍按现契约输出弦线端点**（BStart/BEnd 不变）——插件端先按弦线建直梁再标记；
4. 弧的几何参数（圆心/半径/矢高）**本期不需要**；如日后要自动生成弧梁再另行评审扩列
   （如 BArcCenterX/Y、BArcRadius），本次不要加，避免契约膨胀；
5. 无弧梁的模型：BIsArc 全 0，行为零变化（零回归）。

## 3. 合并语义（插件端将按此实现，请 Python 侧知悉）

插件端梁合并按"平面共线+同截面+共端点"续接，弧梁弦线可能与相邻直段共线被误并。
插件端将在合并中**跳过 BIsArc=1 的段**（类似现有零长度段处理），使每根弧梁独立
成一根直梁输出（CombineBeam 中单根、两端即弧梁起终点），随后染色+注释"弧梁:手改"。
—— 因此 Python 侧无需为合并做任何额外处理。

## 4. 验收标准

1. 颛桥 `dtlmodel.ydb` 重转后：`SELECT count(*) FROM tbl1 WHERE BIsArc=1` 返回实际弧梁数
   （数量请 Python 侧实测后在 result/warning 中报告，双方以同一数字验收）；
2. 无弧梁模型（如 dtlmodel-斜屋面）BIsArc 全 0，其余列逐值不变；
3. 回归测试通过；exe 重打包并同步两个部署位。

## 5. 验证协作

列上线后通知插件端：插件端实现染色（红色实体+注释"弧梁:手改"）→ 颛桥重导 →
抽查弧梁位置染色正确，闭环记录入库。
