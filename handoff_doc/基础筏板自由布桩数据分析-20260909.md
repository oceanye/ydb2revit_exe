# 基础 YDB：筏板分区 + 自由布桩数据分析

日期：2026-09-09  
分支：`feature/foundation-mat-free-piles`  
样本：`基础测试模型/颛桥整体桩基-Jccad_0.ydb`

本文只记录样本分析和接口设计边界，本次没有修改基础读取代码，也没有把样本 YDB 纳入 Git。

## 1. 样本结论

该文件不是当前实现的“承台型号 + 承台实例 + 承台内桩阵列”模式：

- `RaftSlab`：14 条筏板区域记录；
- `RaftCornerPoint`：14 组边界点，共 134 点；
- `app_Pile`：801 条逐根桩记录；
- `app_dais`、`DEF_dais`、`dais_pt`、`dais_stepH`：均为空；
- 当前 `foundation_handoff.py` 读取该文件会报 `foundation YDB contains no pile-cap definitions`。

因此新模式的基本对象应是“筏板楼板 + 单根桩”：

```text
筏板楼板 = 多边形 + 厚度 + 底标高/来源标识 → Revit Floor/楼板实体
单根桩   = 世界坐标逐根记录 + 桩型 + 桩顶/桩底标高语义 → Revit 单根桩实例
```

不能复用 `tbl6` 的承台型号和 `tbl7` 的承台布置来表达自由桩；否则会制造虚假的承台中心、旋转和可复用桩阵列。
新模式不创建承台族、不生成承台中心点，也不把多根自由桩压缩成一个可复用承台型号；筏板区域和单根桩都应保留源 ID 与 Revit 回写 ID。

## 2. 原始表的字段与数量

### 2.1 筏板区域

`RaftSlab` 关键字段：

| 字段 | 样本观察 | 暂定用途 |
|---|---:|---|
| `ID` | 1–14 | 筏板记录行号，不是几何组唯一键 |
| `lID` | `1,3,4,5,6,7,8,9,10,2,11,12,13,14` | 本样本应作为 `RaftCornerPoint.RaftID` 的几何关联键 |
| `thick` | 500 / 800 / 1000 | 区域厚度，单位 mm |
| `BotElevat` | -10.2、-10.0、-9.7、-6.3、-6.1、-5.8 | 区域底标高，单位 m；需在实现中统一转为 mm |
| `baseZ` | -7200 或 -3500 | 另一个标高/楼层基准字段，不能直接当作筏板顶标高 |
| `nMainRaftId` | 全部 -1 | 本样本没有父筏板关系 |
| `RaftParam` | `-1,-1` | 参数字符串，暂不解释为几何 |

`RaftCornerPoint` 按 `RaftID` 分组。不能使用 `RaftSlab.ID` 直接连点；例如 `RaftSlab.ID=2` 的 `lID=3` 对应 `RaftCornerPoint.RaftID=3`。样本中边界点存在顺、逆时针混合，写入中间库前应统一多边形方向并检查零面积。

### 2.2 自由桩

`app_Pile` 共 801 条，关键字段的样本状态：

| 字段 | 样本值/分布 | 判断 |
|---|---|---|
| `ID` | 1–801 | 逐根桩源 ID，应保留为稳定追溯键 |
| `x/y` | 世界平面坐标 | 单位 mm，不是承台局部坐标 |
| `z` | -10200/-10000/-9700/-6100/-5800 | 逐根桩的标高字段；具体是桩顶还是桩底需用 YJK 剖面/界面再确认 |
| `kind` | 全部 0 | 与 `DEF_Pile.ID` 的映射需确认；样本仅有一个桩型，可先支持单型回退 |
| `DaisFlag` | 全部 -1 | 明确表示不属于承台桩阵列 |
| `idUp` | 全部 0 | 没有承台/上部对象关联 |
| `idaispilelen` | 全部 25.0 | 样本桩长，单位看起来为 m，应转为 25000 mm |
| `fKn/fKm/fALFQ` | 全部 0 | 未发现倾斜桩分量；本样本可按竖直桩处理 |

标高分组数量为：`-10200:177`、`-10000:168`、`-9700:161`、`-6100:169`、`-5800:126`。

`DEF_Pile` 只有 1 条：`B=600`、`H=0`、`F1=1400`、`F2=250`、`means=3`、`blade_D=200`、`blade_dis=500`。其中 `B=600,H=0` 表现为圆桩直径 600 mm；`F1/F2` 是承载/设计参数，不能当作桩长。

## 3. 不能采用的简单关联方式

本样本的筏板多边形在平面上有重叠，且不同区域有不同标高/厚度。对 801 根桩只做 XY 点落区判断，会得到：

- 614 根落入多个多边形；
- 50 根不落入任何多边形；
- 同一 XY 区域可能同时对应不同 `BotElevat` 和 `thick`。

所以第一版不能把 `HostRaftRegionID` 强行按 XY 唯一推导。建议：

1. 筏板区域逐区输出，保留 `RaftSlab.ID`、`lID`、厚度、原始底标高和完整边界；
2. 自由桩逐根输出，至少保留源 ID、X/Y、原始 Z、桩型和桩长；
3. `HostRaftRegionID` 先允许为空；只有确认 YJK 的 Z 语义和区域归属规则后再增加确定性关联；
4. Revit 端按筏板区域生成楼板实体，按自由桩表逐根生成桩，不创建虚拟承台。

## 4. 建议的中间库扩展

保留现有承台模式的 `tbl5`–`tbl7`，新增独立表，避免破坏已交付的承台导入：

```text
tbl8  RaftFloorRegion
      RegionKey, SourceRaftID, SourceLID, PolygonJson,
      Thickness, BottomZ, BaseZ, ParentRegionID, RvtID

tbl9  FreePile
      SourceID, X, Y, Z, PileTypeID, Length,
      Kind, DaisFlag, SourceUpperID, HostRegionID, RvtID
```

建议新增能力元数据：

```text
Foundation.Scope = RAFT_REGIONS_FREE_PILES
Foundation.ContractTables = tbl5,tbl8,tbl9
Foundation.ContractVersion = RAFT_FREE_PILES_V1
```

`tbl5` 仍可复用来承载桩型和桩配筋补录；`tbl8` 每行对应一个楼板区域，`tbl9` 每行对应一根单桩。`tbl6`、`tbl7` 在该模式下应为空或保持上一次承台数据的范围清理规则，不能让 Revit 误认为存在承台布置。

## 5. 实施前必须确认的 4 个问题

1. `app_Pile.z` 是桩顶绝对标高、桩底绝对标高，还是相对筏板标高；
2. `app_Pile.kind=0` 与 `DEF_Pile.ID=1` 的映射规则，及多桩型文件的映射；
3. `RaftSlab.BotElevat`、`thick`、`baseZ` 的准确几何语义和单位；
4. 筏板区域与自由桩的归属是否由 YJK 另有关系表/编码，不能仅依靠 XY 点包含关系。

确认这 4 项后，再实现 `raft_free_piles` 读取分支、目标表、回归夹具和 Revit handoff。当前分支已建立，样本分析完成，生产数据尚未改变。
