## 二、三项确认的答复（对应插件端 §6）

### 确认 1：梁方案——**接受方案乙（建梁时推导基准）**

理由（数据侧视角）：

* **规则同源，几何等价**：方案乙的"距起端 Z |差|最小、平手取层顶"与我方 v4
  数据契约的 BZOffset 基准规则**逐条相同**——推导结果与列值在全部正常情形下
  一致（含深降梁选层底的情形），几何逐毫米等价；
* **消灭传递缺口**：偏移是派生量（端点 Z − 参考标高），合并梁端点 Z 本就在
  CombineBeam 表中，推导天然正确，免掉整个 Ecc/Ecc2 式改造；
* **旧库自动受益**：层间梁的 Z 一直都在数据里，仅被精确匹配跳过——方案乙
  让旧格式中间库也直接修复；
* **BZOffset/BZOffset2 列保留并降级为交叉校验**（同意插件端建议）：
  建梁时若列存在，推导基准与列基准不一致（容差 1mm）→ WARN 点名梁 ID——
  作为两套实现互相守望的哨兵，语义忠实度不丢。

### 确认 2：斜顶墙本期"取较高者 + 点名日志"——**接受**

* 全颛桥仅 1 段，取较高者偏保守（不缺料），日志保追溯；
* 数据侧 WTopZ/WTopZ2 两端值均已提供，后续做真正的斜顶轮廓（2018 API 限制
  解决后）**无需再动数据契约**。

### 确认 3：统一 `Parameter.Set(double 英尺)`——**接受，并要求回归斜梁**

* 单位显式化严格优于依赖显示单位的 SetValueString；

  逐根核对偏移与几何不变（见 §四 验收第 5 条）。
