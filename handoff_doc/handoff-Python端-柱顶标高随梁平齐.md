# Handoff：柱顶标高"随梁平齐"未导出（CEndZ 硬编码层顶）

提出日期：2026-09-04
提出方：Revit 插件端（CreateNewExtern 维护）
现象：用户实测（项目2，即 `颛桥测试版\dtlmodel.ydb` 的导入成果，ID 222500 柱）：
YJK 中柱顶标高**与梁顶平齐**，Revit 模型里柱顶到层顶——不平齐。
经查为**转换器侧未导出柱顶调整**。
另：用户同批反馈的 3 面墙（292970/292972/293074）同源——ydb 中
tblWallSeg.HDiff1/2 为 0，墙顶调整信息同样缺失，一并请 YJK 侧核查（见 §4）。

## 1. 已核实事实（无需再调研）

* 转换器 `ydb转换.py` 的 tbl2 构造（`tbl2_rows.append`，约 726 行）：
  ```python
  CStartZ = bottom_z（楼层底）
  CEndZ   = top_z（楼层顶）        # ← 硬编码，未读任何柱顶调整字段
  ```
* ydb `tblColSeg` 实际列：`…EccX,EccY,Rotation,HDiffB,ColcapId,…,ExtLength`；
  **颛桥两份 ydb（dtlmodel 1603 柱 / 斜屋面 36 柱）的 `ExtLength`、`HDiffB` 全为 0**
  ——柱顶"平齐梁顶"没有以任何非零字段形式落库；
* 结论：柱顶随梁的规则属 YJK **运行时行为**（如"柱顶高度=自动/随梁"模式），
  导出数据里既无标志也无数值。

## 2. 修改要求（输出契约，需先经 YJK 侧确认规则）

**前置问题（请 YJK 侧答复）**：柱顶"平齐梁顶"的判定规则是什么？
典型猜想：柱顶 = 该柱节点处**相连梁的最高梁顶 Z**（梁顶=层顶+HDiff），
当其低于层顶时柱随之降；无相连梁时保持层顶。若规则确认如此（或类似）：

1. 转换器在 tbl2 输出前按规则**推导 CEndZ**（直接写入真实顶标高，不新增列，
   与 WTopZ 同思路；同节点相连梁取自 tbl1 输出集合即可）；
2. 无相连梁 / 规则不适用 / 规则未确认期间 → 维持 CEndZ=层顶（现状），
   并对"因规则被下调的柱"在 result/warning 中点名（数量+典型样例）；
3. tbl2 列布局不变（CEndZ 语义从"层顶"变为"真实顶标高"，仅此一处）。

## 3. Revit 插件端将同步实现（本 handoff 附件，供知悉）

CEndZ 脱离整标高后，插件现行"按 Z 精确匹配顶部标高（1mm）"会失败，将同步改为
**与梁同款方案乙**：顶部标高取距 CEndZ 最近的 tbl3 标高（平手取高）+
`顶部标高偏移`参数写入真实顶。插件端改动待本 handoff 落地后实施（半天内）。
