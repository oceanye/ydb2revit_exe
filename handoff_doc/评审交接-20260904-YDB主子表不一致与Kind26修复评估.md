# Handoff：YDB 截面主/子表不一致问题评审与后续提示要求

更新日期：2026-09-04  
评审角色：代码/数据链路评审（本次不修改转换器、测试或打包产物）  
评审对象：`技术说明-20260903-梁缺失方案A与PEC截面主子表矛盾修复.md`、当前 `main`、远端 `dev-wangxinyu` 的相关提交

## 1. 评审结论

本问题不是“YDB 或转换器二选一”，而是两个层次叠加：

1. **输入层问题**：原始 YDB 对同一个 `SectID` 的主表和子表保存了互相矛盾的截面定义。
2. **转换层问题**：当前 `ydb2revit_exe` 没有做一致性校验，并且在 `Kind=209` 时优先采用主表数值，因而把矛盾放大成了 Revit 中的错误截面。

责任边界应记录为：

> YDB 是脏数据/不一致输入；转换器是未识别该输入并选择错误来源的兼容性缺陷。转换器不会在正常流程中把主表和子表写成矛盾，但会根据矛盾数据生成错误的 `tbl1/tbl2` 截面。

当前评审不建议把该问题标记为“已完全解决”。对已知的 1117 形态，提交的修复方向正确；作为通用的 YDB 数据质量防护，还需要补上数值子表冲突、重复子表、用户提示和非交互模式等要求。

## 2. 已确认的事实

### 2.1 1117 的原始矛盾

技术说明记录的三方数据如下：

| 来源 | 记录 | 解释 |
|---|---|---|
| `tblBeamSect` 主表 | `Kind=209`，`t/d/u/f=350/150/6/11` | `H350x150x6x11`，被判断为陈旧值 |
| `tblSubSectionSect` 子表 | `SubKind=26`，短格式 `ShapeVal` | 解码为标准目录 `HW200X200`，Q16 高宽为 `200/200` |
| YJK 界面 | 类型 1 `HW200X200` | 与子表目录定义一致 |

因此，主子表矛盾在转换前已经存在。仅凭现有资料可以确认“YDB 包内部不一致”，但要把责任继续追溯到 YJK 建模、YJK 导出器或其他中间工具，仍需拿到原始 YJK 模型、导出前后文件或上游导出日志。技术说明中“修改截面后没有刷新主表”的说法应作为成因推断，不应当作已经独立证明的事实。

### 2.2 当前转换器的行为

当前 `ydb转换.py`：

- 以只读 URI 打开源 YDB，并写入另一个目标 SQLite 库；正常转换不会修改源 `tblBeamSect` 或 `tblSubSectionSect`。
- 对 `Kind=209` 的尺寸解析先取主表 `t/d/u/f`，子表数值只作为缺省回退。
- 未解析 `Kind26` 短格式，也未在主表和子表之间做差异报警。

因此，用 1117 的原始值运行旧逻辑会得到 `H350x150x6x11@PEC`。这属于转换结果错误，不是转换器制造了源数据矛盾。

### 2.3 与“梁缺失”的边界

文档中的 `tbl3`/构件标高补集导致的 Z=400 梁缺失，是另一条链路：它表现为构件没有进入输出或 Revit 建模阶段；截面主子表矛盾表现为构件存在但截面类型错误。两者应分别统计、分别验收，不能用“梁数量恢复”代替截面一致性验收。

### 2.4 历史判断

- 2026 年 1 月已有 PEC `Kind=209` 的支持和子表复制逻辑，但没有建立主子表一致性不变量。
- 2026 年 8 月重构后的 `main` 仍保留“主表优先、无校验”的行为，因此风险长期存在。
- 可检索的远端历史中，`SectID=1117` 的真实案例首次被明确记录在 2026-09-03；不能据此断言此前从未有同类数据，只能说此前没有找到明确记录。

### 3.1 方案有效的部分

`399a825` 的方向对 1117 是有效的：

1. 支持 `Kind26` 长格式和 11 字段短格式。
2. 对选择器、名称、Q16 高宽以及长格式尾部 ID 做交叉校验。
3. 可验证的子表目录定义优先于主表陈旧数值。
4. 无可用子表时保留主表回退，并把回退写入 `warnings`。
5. 增加了 1117 类“主表 H350、子表 HW200”的回归测试。

提交说明声称颛桥重转后得到 `H200X200X8X12@PEC`，且用户抽查的 6 根梁正确。由于评审环境没有文档所述的颛桥原始 YDB，数量和人工抽查结果应保留为提交方的现场验收证据，不能由本地独立复现确认。

### 3.2 合入前必须补充/复核的事项

以下事项使当前方案只能评为“针对 1117 基本有效”，不能评为“通用问题已闭环”：

1. **尚未进入当前 `main`**。`dev-wangxinyu` 还包含其他功能提交，不应整分支直接合并；应隔离移植修复并重新跑主线测试和打包验收。
2. **数值型 `SubKind=13` 冲突仍可能静默**。当前修复主要让成功解码的 `Kind26` 覆盖主表；如果子表有数值但数值与主表不一致，现有逻辑仍可能选择主表，而且不会报警。必须明确比较 `(H,B,tw,tf)` 并记录冲突。
3. **重复子表会被静默覆盖**。`_row_map` 只保留同一 ID 的最后一行。应先检测同 ID 多行，再决定拒绝、选择规则或提示，不能让排序结果隐式决定数据来源。
4. **四段式名称需要增加测试**。当前提交中的四段式解析分支条件对类似 `H400X200X8X13` 的名称未被现有测试覆盖，需确认能正确返回厚度；否则会出现“名称可读但仍回退/拒绝”的边界问题。
5. **应有真实最小样本或脱敏快照**。合成测试只能证明算法路径；至少应保留 1117 主行、子行、引用数量和文件哈希，避免以后只凭现场口述验收。
6. **所有消费者要共用同一解析结果**。梁、普通 PEC 柱、墙端 H 柱都必须验证使用同一套优先级和告警，不得只修梁路径。
7. **输出必须可追溯**。建议在审计报告中保留 `SectID`、来源（子表 Kind26/子表数值/主表回退）、解析前后尺寸和受影响构件数；仅统计最终 `BSection` 无法定位源 ID。

## 4. 后续需求：一次性数据问题弹窗

### 4.1 触发时机

在转换开始、源 YDB 已以只读方式打开且完成截面预扫描后触发。不要等转换完或 Revit 建模失败后才提示。

一次转换运行只弹一次。多个截面或多个构件的异常应聚合到同一个提示中，不能逐构件弹窗。

### 4.2 触发条件

至少包括：

- `Kind=209` 主表与 `SubKind=13` 数值子表的 H/B/tw/tf 有效值不一致（建议容差 `0.5 mm`）。
- 子表 `SubKind=26` 成功解码出的目录名称/Q16 尺寸与主表数值不一致。
- 同一 `SectID` 有多个子表候选，且候选之间不一致。
- 子表存在但无法解码，同时主表有可用回退值。

“主子表一致且只是正常双源互证”不应提示；只有主表单独回退也应写入报告，是否弹窗可按产品策略设为低级警告。

### 4.3 建议的提示内容

建议文案：

> 检测到当前 YDB 存在截面主表/子表数据不一致，可能导致转换后的 Revit 截面与 YJK 不一致。发现 **N 个截面、M 个构件**受影响（示例：`SectID=1117`，主表 `H350x150x6x11`，子表 `HW200X200`）。建议先在 YJK 修复并重新导出。选择“继续转换”将按兼容方案优先采用通过校验的子表定义；选择“取消”不生成或不覆盖输出数据库。

按钮至少包含：

- **继续转换（按兼容方案）**
- **取消**

弹窗中应显示异常截面 ID、主/子摘要和受影响构件数；完整明细写入同一次转换的审计报告或日志。

### 4.4 继续与取消的语义

- 用户选择“继续”后，本次运行不再重复弹窗；所有异常仍必须进入 `warnings`/审计报告。
- 继续时的解析优先级应固定为：通过校验的 `Kind26` 子表 → 一致的数值子表 → 主表回退；回退必须点名，不能静默。
- 用户选择“取消”时，不应生成半成品，也不应覆盖已有正式输出库。
- 告警扫描失败、数据库损坏或无法确定来源时，应按安全策略停止，不应把“不确定”当成可继续。

### 4.5 命令行和无人值守

命令行/批处理没有可靠的交互窗口时，不应静默继续。应输出机器可读的异常摘要，并由调用方显式指定“允许按兼容方案继续”的策略；默认建议停止并保留报告。GUI/EXE 的一次性弹窗只负责交互，不应改变审计记录。

## 5. 建议验收用例

### A. 已知 1117 矛盾

- 主表：`350/150/6/11`。
- 子表：短格式 `Kind26`，`HW200X200`，Q16 `200/200`。
- 预期：弹一次提示；选择继续后输出 `H200X200X8X12@PEC`；报告记录来源为“子表 Kind26”；不得输出 `H350X150X6X11@PEC`。

### B. 一致的 `SubKind=13`

- 主表和子表数值相同。
- 预期：不弹矛盾提示，不产生冲突告警，输出尺寸不变。

### C. 数值型子表冲突

- 主表和 `SubKind=13` 都有值但不同。
- 预期：必须被检测并列入一次性提示；继续时要有明确的来源选择和审计记录。

### D. 重复子表

- 同一 ID 插入两条不同候选。
- 预期：不能由 `_row_map` 静默取最后一条；应提示并记录全部候选。

### E. 不可解码子表/主表回退

- 子表存在但格式非法，主表有完整尺寸。
- 预期：提示“YDB 数据存在问题”；继续可按主表回退，但必须点名 `SectID` 和构件数。

### F. 取消与源文件保护

- 在提示框选择取消。
- 预期：输出库不新建或不覆盖；源 YDB 文件哈希不变化。

### G. 梁、柱、墙端 H 全链路

- 同一异常截面分别被梁、独立 PEC 柱和墙端 H 引用。
- 预期：三种输出使用同一解析结果，统计和审计数量一致。

## 6. 最小排查 SQL

```sql
SELECT
    m.ID,
    m.ShapeVal AS MainShape,
    m.h, m.b, m.u, m.t, m.d, m.f,
    s.Kind, s.SubKind,
    s.ShapeVal AS SubShape,
    s.h, s.b, s.u, s.t, s.d, s.f
FROM tblBeamSect m
LEFT JOIN tblSubSectionSect s ON s.ID = m.ID
WHERE m.Kind = 209
ORDER BY m.ID;
```

影响范围：

```sql
SELECT SectID, COUNT(*) AS SegmentCount
FROM tblBeamSeg
GROUP BY SectID
ORDER BY SegmentCount DESC;
```

审计时还应检查：

```sql
SELECT ID, COUNT(*) AS CandidateCount
FROM tblSubSectionSect
GROUP BY ID
HAVING COUNT(*) > 1;
```
